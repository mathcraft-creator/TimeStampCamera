# 화면 방향 연동 카메라 프레임 및 줌 설계

## 목표

기기의 화면 방향이 바뀌면 카메라 화면과 촬영 프레임도 같은 방향에 맞춰 자동으로 전환한다. 사용자가 선택한 사진 비율은 방향과 무관한 기준 비율로 저장한다. 핀치 제스처와 화면 버튼으로 카메라를 확대·축소할 수 있게 한다.

## 동작 요구사항

| 설정에서 선택한 비율 | 세로 화면 프레임 | 가로 화면 프레임 |
| --- | --- | --- |
| 3:4 | 3:4 | 4:3 |
| 9:16 | 9:16 | 16:9 |
| 1:1 | 1:1 | 1:1 |

- 앱의 세로 화면 고정을 제거하고 기기 회전을 허용한다.
- 설정 화면에는 기존 선택지인 `3:4`, `9:16`, `1:1`만 표시한다.
- 저장된 설정 형식과 기존 사용자 설정은 변경하지 않는다.
- 카메라 화면뿐 아니라 설정 화면도 시스템의 화면 방향을 따른다.
- 프레임 위의 두 손가락 핀치와 `− / +` 버튼을 모두 지원한다.
- 미리보기와 저장 사진에 동일한 CameraX 줌 배율을 적용한다.

## 설계

### 방향별 프레임 비율 계산

현재 화면이 가로인지 여부와 `StampAspectRatio`를 입력받아 Compose `aspectRatio`에 전달할 너비/높이 값을 반환하는 순수 함수를 추가한다. 가로 화면에서는 `3:4`를 `4/3`, `9:16`을 `16/9`로 뒤집고, 세로 화면과 `1:1`에서는 기존 값을 사용한다.

`CameraScreen`은 Compose의 현재 configuration에서 화면 방향을 읽는다. 방향이 바뀌면 recomposition을 통해 프레임 크기가 즉시 갱신된다.

### CameraX 연동

CameraX가 지원하는 타깃 종횡비는 방향 표기와 무관하게 센서 계열을 선택하므로, `9:16` 기준 설정에는 `AspectRatio.RATIO_16_9`, `3:4` 및 `1:1`에는 `AspectRatio.RATIO_4_3`을 계속 사용한다. 방향 변경을 `LaunchedEffect` 키에 포함해 새 surface 방향에 맞춰 Preview와 ImageCapture를 다시 바인딩한다.

촬영 시 CameraX가 제공하는 회전 정보를 적용하는 기존 이미지 변환 경로를 유지한다. `1:1`은 기존 중앙 정사각형 크롭을 그대로 사용한다. `3:4`와 `9:16`은 선택된 CameraX 소스 계열과 기기 방향을 통해 각각 `3:4`/`4:3`, `9:16`/`16:9` 결과가 된다.

### 화면 배치

카메라 프레임은 화면 중앙에 배치한다. 가로 화면에서는 프레임의 너비뿐 아니라 사용 가능한 높이도 제약하므로, 프레임이 화면 밖으로 넘치지 않도록 가용 영역 안에서 선택 비율을 유지하는 크기로 맞춘다. 테두리, 각인 미리보기, 로고는 프레임과 동일한 컨테이너 안에 두어 방향 전환 후에도 촬영 영역과 정렬되게 한다. 카메라 전환, 뷰티, 설정, 촬영 버튼은 전체 화면 오버레이로 유지한다.

### 줌 제어

CameraX 바인딩 결과의 `CameraControl`과 `CameraInfo.zoomState`를 사용한다. 핀치 제스처는 현재 배율에 제스처의 확대 비율을 곱해 연속적으로 `setZoomRatio`에 전달한다. `− / +` 버튼은 기기가 보고한 최소·최대 줌 범위 안에서 일정한 비율 단계로 배율을 낮추거나 높인다. 모든 입력은 지원 범위로 제한한다.

화면에는 `−`, 현재 배율(예: `1.0×`), `+`를 하나의 줌 컨트롤로 표시한다. 세로·가로 화면에서 촬영 버튼과 겹치지 않는 하단 영역에 배치한다. 현재 배율 표시는 CameraX의 실제 `zoomState`를 관찰해 요청값과 하드웨어 적용값이 달라도 실제 상태를 보여 준다.

화면 회전으로 Preview와 ImageCapture가 다시 바인딩될 때는 현재 배율을 새 CameraControl에 다시 적용한다. 전면·후면 카메라를 사용자가 전환하면 새 카메라의 지원 범위가 달라질 수 있으므로 `1.0×`로 초기화한다. 줌 배율은 앱 설정에 저장하지 않으며 카메라 화면을 새로 시작하면 `1.0×`에서 시작한다.

## 오류 및 호환성

- 화면 회전 중 CameraX 재바인딩 실패는 앱을 종료시키지 않으며 기존 오류 처리 방식을 유지한다.
- 줌 요청 실패 또는 카메라가 제한된 줌 범위만 제공하는 경우 지원 범위 안의 현재 배율을 유지한다.
- 기존 SharedPreferences의 비율 enum 이름을 바꾸지 않아 마이그레이션이 필요 없다.
- 멀티윈도우에서도 Android configuration이 보고하는 현재 UI 방향을 기준으로 프레임을 결정한다.

## 테스트 및 검증

- 순수 비율 계산에 대해 다음 단위 테스트를 작성한다: 세로 `3:4`, 세로 `9:16`, 가로 `4:3`, 가로 `16:9`, 양 방향 `1:1`.
- 줌 계산에 대해 확대, 축소, 최솟값 제한, 최댓값 제한을 단위 테스트한다.
- 카메라 전환 시 `1.0×` 초기화와 화면 회전 시 배율 유지 정책을 상태 테스트 또는 분리한 순수 로직 테스트로 검증한다.
- 테스트를 먼저 실패시키고 최소 구현으로 통과시킨다.
- 전체 단위 테스트와 Gradle 빌드를 실행한다.
- 가능하면 세로/가로 configuration에서 Compose 프레임이 화면 경계를 넘지 않는지 확인한다.

## 제외 범위

- 방향별로 서로 다른 비율을 별도 저장하는 기능
- 설정 화면에 `4:3`, `16:9` 선택지를 추가하는 변경
- 버튼 배치나 카메라 UI의 전면 재설계
- 줌 배율 영구 저장, 프리셋 렌즈 버튼 또는 촬영 후 추가 디지털 크롭
- 사진 EXIF 정책 또는 갤러리 저장 위치 변경
