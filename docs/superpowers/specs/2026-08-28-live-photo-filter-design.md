# 실시간 사진 필터 설계

## 목표

기존 뷰티 보정과 함께 사용할 수 있는 감성 색감 필터를 추가한다. 사용자는 촬영 전에 카메라 미리보기에서 효과를 확인하고, 선택한 프리셋과 강도가 저장 사진에도 적용되도록 한다.

이번 범위는 외부 이미지 처리 라이브러리나 얼굴 인식 모델을 추가하지 않고 Android `ColorMatrix`와 CameraX의 기존 미리보기 구조를 활용하는 데 한정한다.

## 사용자 경험

카메라 화면에 `🎨 필터` 버튼을 추가한다. 버튼을 누르면 촬영 버튼 위에 반투명 패널이 열리고, 다음 요소를 표시한다.

- 필터 강도 슬라이더 `0~100`
- 가로로 스크롤할 수 있는 필터 썸네일 8개
- 선택된 필터의 분홍색 테두리와 강조된 이름

지원 프리셋은 다음과 같다.

1. 원본
2. 화사함
3. 따뜻함
4. 차가움
5. 흑백
6. 빈티지
7. 선명함
8. 페이드

썸네일은 카메라 영상을 여러 번 렌더링하지 않는다. 앱에 포함된 작은 중립 색상 샘플에 각 프리셋을 적용해 차이를 보여주고, 현재 촬영 장면의 실제 결과는 메인 미리보기에서 확인한다.

썸네일을 누르면 효과가 메인 미리보기에 즉시 반영된다. 패널 바깥이나 필터 버튼을 다시 누르면 패널이 닫힌다. 패널이 열린 상태에서도 촬영할 수 있다. 화면 방향이 바뀌면 패널을 닫지 않고 새 방향의 카메라 프레임과 조작 영역에 맞춰 재배치한다.

`원본`에서는 강도 슬라이더를 비활성화한다. 다른 프리셋은 공통 강도 값을 사용하며, 프리셋을 바꿔도 마지막 강도를 유지한다. 선택한 프리셋과 강도는 앱을 다시 실행해도 유지한다. 기본 프리셋은 `원본`, 기본 강도는 `100`이다.

뷰티 버튼과 필터 버튼은 서로 독립적으로 동작한다. 사용자는 뷰티만, 필터만, 둘 다, 또는 둘 다 사용하지 않는 상태를 선택할 수 있다.

하단 조작 영역은 촬영 버튼을 화면의 수평 중앙에 고정한다. 촬영 버튼 왼쪽에는 `✨뷰티`와 `🎨필터` 버튼을 나란히 두고, 오른쪽에는 카메라 `전환` 버튼을 둔다. 기존 좌측 상단의 전환 및 뷰티 버튼은 제거하며, 설정 버튼은 우측 상단에 유지한다. 필터 패널은 이 하단 버튼 행 위로 열려 어느 화면 방향에서도 촬영 버튼과 겹치지 않아야 한다.

## 아키텍처

### `PhotoFilterPreset`

필터 프리셋을 나타내는 enum이다. 영속 저장용 안정적인 식별자, 사용자에게 표시할 한글 이름, 최대 강도의 색상 변환 파라미터를 소유한다. enum 이름 자체가 아니라 별도의 안정적인 식별자를 저장해 코드 이름 변경이 기존 설정을 깨뜨리지 않게 한다.

알 수 없는 저장값은 `원본`으로 해석한다.

### `PhotoFilter`

프리셋과 `0~100` 강도를 입력받아 Android `ColorMatrix`를 생성하고, 저장용 Bitmap에 효과를 적용한다.

강도는 항등 행렬과 프리셋의 최대 강도 행렬 사이를 선형 보간한다.

- 강도 `0`: 항등 행렬과 동일하며 원본 색상을 보존
- 강도 `100`: 프리셋의 전체 효과
- `원본`: 강도와 관계없이 항등 변환

Bitmap 처리 함수는 변환이 필요 없으면 입력 Bitmap을 그대로 반환한다. 새 Bitmap을 반환한 경우에만 호출자가 이전 Bitmap을 해제한다.

### 미리보기 필터 적용

CameraX `PreviewView`의 구현 모드를 `COMPATIBLE`로 설정해 `TextureView` 기반 미리보기를 사용한다. `PhotoFilter`가 만든 것과 동일한 색상 행렬을 `ColorMatrixColorFilter`로 변환하고, 미리보기 View의 하드웨어 레이어 Paint에 적용한다.

프리셋이나 강도가 바뀌면 CameraX use case를 다시 바인딩하지 않고 View의 필터만 갱신한다. `원본`으로 돌아가면 색상 필터를 제거한다.

미리보기 적용 코드는 프리셋 정의와 Bitmap 처리 코드에서 분리한다. 향후 OpenGL 또는 CameraX `CameraEffect` 기반으로 교체하더라도 프리셋, 설정 저장, 촬영 후 처리 코드는 유지할 수 있어야 한다.

### 설정 저장

`StampConfig`와 기존 SharedPreferences 저장소에 다음 값을 추가한다.

- 선택한 필터의 안정적인 문자열 식별자
- 공통 필터 강도 정수

강도는 불러올 때 `0~100` 범위로 제한한다. 기존 사용자에게 저장값이 없으면 `원본`, `100`을 사용하므로 앱 업데이트만으로 기존 사진 색상이 달라지지 않는다.

## 데이터 흐름

필터 선택이나 강도 변경 시 Compose 상태와 영속 설정을 갱신하고, 계산된 색상 행렬을 미리보기에 즉시 전달한다.

촬영 버튼을 누르는 시점의 전체 설정 스냅샷을 촬영 처리 작업에 전달한다. 저장 작업이 진행되는 동안 사용자가 필터를 바꿔도 이미 촬영한 사진에는 촬영 시점의 프리셋과 강도를 사용한다.

촬영 결과 처리 순서는 다음과 같다.

1. `ImageProxy`를 방향 보정된 Bitmap으로 변환
2. 선택한 사진 비율로 크롭
3. 뷰티가 활성화된 경우 잡티 보정과 화사함 적용
4. 선택한 색감 필터와 강도 적용
5. 날짜, 위치, 메모, 로고와 테두리 합성
6. 갤러리에 저장

색감 필터를 각인과 테두리보다 먼저 적용해 텍스트, 로고와 테두리의 지정 색상을 보존한다.

## 성능과 자원 관리

프리셋 변경은 색상 행렬과 View 레이어만 갱신하며 카메라 세션을 재시작하지 않는다. 강도 슬라이더 입력도 같은 경로를 사용해 연속 조작 중 미리보기 중단이 없어야 한다.

썸네일은 고정된 작은 샘플 하나를 공유하고 각 프리셋의 색상 변환만 다르게 렌더링한다. 별도의 CameraX 스트림이나 프레임 분석 use case를 추가하지 않는다.

저장 처리에서는 불필요한 Bitmap 복사를 피한다. 필터가 새 Bitmap을 만들 때 이전 중간 Bitmap을 즉시 해제하고, 최종 저장 과정에서 사용하는 Bitmap의 소유권 규칙을 기존 뷰티 처리와 일관되게 유지한다.

`TextureView` 기반 미리보기는 기본 `SurfaceView`보다 일부 기기에서 전력과 GPU 사용량이 조금 늘 수 있다. 이 비용은 Android 10 이상에서 라이브 색상 필터를 단순하고 일관되게 제공하기 위한 허용 가능한 절충으로 본다.

## 오류 처리와 호환성

미리보기 하드웨어 레이어 또는 색상 필터 적용이 기기에서 실패하면 예외로 카메라 화면을 종료하지 않는다. 해당 세션의 미리보기 필터를 제거하고 원본 미리보기를 유지한다. 저장 사진의 Bitmap 필터 처리는 계속 시도한다.

저장 사진의 필터용 Bitmap 생성이나 변환이 실패하면 필터 적용 전 Bitmap으로 나머지 각인과 저장을 계속 시도한다. 최종 저장까지 실패한 경우에만 기존의 `저장 실패` 토스트를 표시한다. 미리보기 필터만 실패한 경우 반복 토스트를 표시하지 않는다.

미리보기와 JPEG/Bitmap 저장 경로의 색 공간과 렌더링 방식이 달라 결과가 픽셀 단위로 완전히 같지는 않을 수 있다. 성공 기준은 동일한 프리셋의 방향성, 상대 강도, 명암과 색온도가 육안상 일치하는 것이다.

최소 지원 버전은 현재와 동일한 Android 10(API 29)이며 이를 올리지 않는다.

## 테스트와 검증

### 자동 테스트

- 8개 프리셋이 고유하고 유효한 안정적 식별자를 갖는지 검사
- 프리셋별 강도 `0`, `50`, `100`의 행렬 계산 검사
- 모든 프리셋의 강도 `0`이 항등 행렬인지 검사
- `원본`이 모든 강도에서 항등 행렬인지 검사
- 범위를 벗어난 강도가 `0~100`으로 제한되는지 검사
- 알 수 없는 프리셋 저장값이 `원본`으로 복구되는지 검사
- 설정 저장과 복원 시 프리셋 및 강도가 유지되는지 검사
- 필터가 비활성인 경로에서 입력 Bitmap을 그대로 반환하는지 검사

### 실제 기기 검증

- 전면 및 후면 카메라에서 8개 필터 전환
- 강도 슬라이더를 빠르게 이동해도 프리뷰 정지나 카메라 재시작이 없는지 확인
- 세로와 가로 화면 전환 후 패널, 썸네일, 촬영 버튼과 각인 미리보기의 배치 확인
- 전체 비율과 1:1 크롭에서 미리보기와 저장 결과 비교
- 뷰티만, 필터만, 둘 다, 둘 다 끈 조합의 저장 결과 확인
- 필터 패널이 열린 상태의 촬영과 연속적인 필터 변경 후 촬영 확인
- 앱 재시작 후 마지막 프리셋과 강도 복원 확인
- 미리보기 필터 실패 시 원본 미리보기와 필터 적용 저장 경로가 유지되는지 확인 가능한 기기에서 검증

주 검증 기기는 프로젝트가 현재 대상으로 삼는 갤럭시 노트20 울트라와 Android 10 이상 기기다.

## 제외 범위

- 얼굴 또는 피부 영역만 분리해 적용하는 ML 기반 보정
- 사용자 정의 LUT 가져오기
- 동영상 촬영 필터
- 필터별 개별 강도 기억
- 필터 조합 또는 사용자 프리셋 생성
- OpenGL 셰이더나 CameraX `CameraEffect`로의 전환

이 항목들은 현재 구현의 안정성과 범위를 유지하기 위해 후속 작업으로 남긴다.
